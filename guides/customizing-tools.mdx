CLAI gives you granular control over the three MCP tools it exposes to AI clients — you can adjust result limits, enable metadata enrichment, cap content length, and disable individual tools entirely. Tuning these settings lets you balance token efficiency, response quality, and privacy across different documentation setups.

## When to customize tools

Most use cases benefit from at least some tool customization. Here are the most common scenarios that call for it:

- **Large documentation sites** — Reducing `maxResults` on the `search` tool prevents the AI from receiving dozens of loosely relevant snippets, keeping responses focused and token costs down.
- **Private or sensitive content** — Disabling `list_pages` stops AI clients from enumerating all available pages, limiting exposure to content the user hasn't explicitly asked for.
- **Context window management** — Setting `maxContentLength` on `get_page` ensures that a single long page never consumes the AI's entire context budget, leaving room for conversation and reasoning.

## Tuning search results

The `search` tool is the most frequently called tool in a typical AI session. Configuring it thoughtfully has the biggest impact on the quality and cost of AI responses.

```json clai.config.json
{
  "tools": {
    "search": {
      "enabled": true,
      "maxResults": 5,
      "includeMetadata": true
    }
  }
}
```

**`maxResults`** controls how many matching pages CLAI returns for each search query. Lower values mean fewer tokens consumed and faster responses, but the AI may miss relevant content on complex queries. Higher values give the AI more material to reason over, at the cost of increased token usage. A value between `3` and `8` works well for most documentation sites.

**`includeMetadata`** enriches each search result with the page's URL, title, and last-modified date. Enabling this helps the AI cite sources accurately and reason about content freshness — recommended for documentation that changes frequently.

## Controlling page content length

Full documentation pages can be very long. The `get_page` tool retrieves complete page content by default, which can exhaust an AI's context window on a single call. Use `maxContentLength` to set a hard character limit on what CLAI returns.

```json clai.config.json
{
  "tools": {
    "get_page": {
      "enabled": true,
      "maxContentLength": 30000
    }
  }
}
```

When a page exceeds `maxContentLength`, CLAI truncates the content at the nearest paragraph boundary and appends a notice indicating the page was truncated. The AI client sees the truncation notice and can request a different page or refine its query.

For most use cases, a value between `20000` and `50000` characters strikes the right balance — it captures the meaningful content of even large reference pages while leaving the AI enough context budget for multi-turn conversations.

## Disabling tools for specific use cases

You can disable any of the three CLAI tools by setting `"enabled": false` in its config block. This is useful when a particular tool doesn't fit your documentation structure or privacy requirements.

**Scenario 1: Disable `list_pages` on large sites**

On a site with hundreds of pages, calling `list_pages` returns an overwhelming list that can confuse the AI or blow through its context limit. Disable it and let the AI rely on `search` to discover content instead.

```json clai.config.json
{
  "tools": {
    "list_pages": {
      "enabled": false
    }
  }
}
```

**Scenario 2: Disable `get_page` for search-only behavior**

If you want the AI to reason only from search snippets without fetching full page content — for example, to enforce stricter token budgets or limit access to the full text of licensed documentation — disable `get_page` entirely.

```json clai.config.json
{
  "tools": {
    "get_page": {
      "enabled": false
    }
  }
}
```

<Warning>
  Do not disable all three tools at the same time. If `search`, `list_pages`, and `get_page` are all set to `"enabled": false`, CLAI starts successfully but exposes no tools to AI clients — they will be unable to retrieve any documentation. Always keep at least one tool enabled.
</Warning>

## Tool naming and descriptions

The names `search`, `list_pages`, and `get_page` are fixed identifiers that match the CLAI MCP specification. AI clients discover available tools by calling the MCP tool-discovery endpoint on the CLAI server — the response lists each enabled tool by its canonical name along with its input schema and description.

You cannot rename the tools, but you can update the `description` field for each tool in your config to give the AI client additional context about your specific documentation. For example, you can clarify that `search` only covers your public API reference, or that `get_page` returns MDX source rather than rendered HTML:

```json clai.config.json
{
  "tools": {
    "search": {
      "enabled": true,
      "description": "Search the ACME public API reference documentation."
    }
  }
}
```

AI clients surface tool descriptions to the underlying model, so a precise description can meaningfully improve how the AI decides which tool to call and when.

## Full tools configuration example

The following example shows all supported options across all three tools in a single config block. Use it as a reference when customizing your own setup:

```json clai.config.json
{
  "tools": {
    "search": {
      "enabled": true,
      "maxResults": 5,
      "includeMetadata": true,
      "description": "Search the ACME API reference and guides."
    },
    "list_pages": {
      "enabled": true
    },
    "get_page": {
      "enabled": true,
      "maxContentLength": 30000
    }
  }
}
```
