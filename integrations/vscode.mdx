title: "Integrate CLAI with VS Code and GitHub Copilot Chat"
sidebarTitle: "VS Code"

---

VS Code's GitHub Copilot extension supports MCP servers through a `.vscode/mcp.json` workspace file — add CLAI to give Copilot direct access to your docs while you code. Because the config lives in the workspace, every member of your team gets the same setup the moment they open the project.

## Prerequisites

- **VS Code 1.99 or later** — MCP support was introduced in this release
- **GitHub Copilot extension** installed and signed in
- CLAI installed and a `clai.config.json` present in your project directory

## Setup

<Steps>
  <Step title="Create the MCP config file">
    Create a new file at `.vscode/mcp.json` in your project root. If the `.vscode/` directory doesn't exist yet, create it — VS Code already uses this directory for other workspace settings like `launch.json` and `settings.json`.
  </Step>

  <Step title="Add the CLAI server">
    Paste the following into `.vscode/mcp.json`:

    ```json
    {
      "servers": {
        "clai": {
          "type": "stdio",
          "command": "clai",
          "args": ["start", "--stdio"]
        }
      }
    }
    ```

    VS Code picks up this file automatically — no restart required. The `type: "stdio"` field tells Copilot to launch CLAI as a subprocess using standard input/output as the transport.
  </Step>

  <Step title="Enable Agent mode in Copilot Chat">
    Open Copilot Chat with **Ctrl+Alt+I** (or via the Copilot icon in the activity bar). Click the **mode selector** at the top of the chat panel — it typically defaults to "Ask" — and switch it to **Agent**. MCP tools are only available in Agent mode.
  </Step>

  <Step title="Verify the connection">
    Click the **tools icon** (a wrench or sparkle symbol) inside the Copilot Chat input area. A dropdown will list every available tool grouped by server. You should see CLAI's tools — `search`, `list_pages`, and `get_page` — listed under the `clai` server. If they appear, the connection is live.
  </Step>

  <Step title="Ask about your docs">
    You're ready. Ask Copilot about your documentation naturally:

    > "How do I configure authentication according to our docs?"
    > "What does the onboarding guide say about environment variables?"

    Copilot will call CLAI's tools and ground its response in your actual documentation rather than its training data. You can also prefix queries with `@workspace` to keep Copilot focused on your project context.
  </Step>
</Steps>

<Note>
  Committing `.vscode/mcp.json` to your repository is safe and recommended. The file is workspace-scoped — it only affects VS Code instances that open that specific project. Every team member who clones the repo and opens it in VS Code 1.99+ will have CLAI available in Copilot Chat without any manual setup.
</Note>

<Tip>
  For remote or distributed teams where running CLAI locally on every machine isn't practical, switch to the HTTP transport instead. Start CLAI with `clai start --http --port 3000` on a shared server, then update `.vscode/mcp.json` to use `"type": "http"` and `"url": "http://your-server:3000/mcp"`. Everyone on the team connects to the same CLAI instance over the network.
</Tip>

## Troubleshooting

<AccordionGroup>
  <Accordion title="CLAI doesn't appear in the tools list">
    If the Copilot tools dropdown doesn't show CLAI's tools, VS Code may not have reloaded the MCP config yet:

    1. **Reload the VS Code window** — open the Command Palette (**Cmd+Shift+P** / **Ctrl+Shift+P**) and run **Developer: Reload Window**. VS Code re-reads `.vscode/mcp.json` on reload.
    2. **Check for JSON errors** — a syntax error in `mcp.json` will silently prevent the server from loading. Open the file and look for red squiggles, or paste the contents into a JSON validator.
    3. **Confirm the file path** — the file must be at `.vscode/mcp.json` relative to your workspace root, not nested deeper or placed in a subdirectory.
    4. **Review the MCP output** — open **View > Output** and select **GitHub Copilot - MCP** from the dropdown for detailed connection logs.
  </Accordion>

  <Accordion title="Getting permission errors">
    If CLAI fails to start with a permissions error, the binary may not be marked as executable:

    ```bash
    chmod +x $(which clai)
    ```

    On macOS, you may also need to allow the binary through Gatekeeper the first time it runs. Open **System Settings > Privacy & Security** and click **Allow Anyway** next to the CLAI entry, or run:

    ```bash
    xattr -d com.apple.quarantine $(which clai)
    ```

    On Windows, ensure the CLAI binary isn't being blocked by your antivirus or Windows Defender. Running VS Code as an administrator for the first launch can help confirm whether permissions are the root cause.
  </Accordion>
</AccordionGroup>
