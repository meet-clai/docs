---
title: "Integrate CLAI with Claude Desktop as an MCP Server"
sidebarTitle: "Claude Desktop"
description: "Register CLAI as an MCP server in Claude Desktop so Claude can search, list, and retrieve your documentation pages during any conversation."
---

Claude Desktop supports MCP servers natively — add CLAI to your configuration file and Claude will automatically discover your docs tools and call them whenever a conversation touches on your documentation. No plugins, no browser extensions, no manual copy-pasting required.

## Prerequisites

- CLAI installed and a `clai.config.json` present in your project directory
- Claude Desktop **version 0.10 or later** ([download here](https://claude.ai/download))

## Setup

<Steps>
  <Step title="Locate the Claude Desktop config file">
    Claude Desktop stores its MCP server configuration in a JSON file on your machine. Open it in any text editor:

    <Tabs>
      <Tab title="macOS">
        ```text
        ~/Library/Application Support/Claude/claude_desktop_config.json
        ```
      </Tab>
      <Tab title="Windows">
        ```text
        %APPDATA%\Claude\claude_desktop_config.json
        ```
      </Tab>
    </Tabs>

    If the file doesn't exist yet, create it — Claude Desktop will pick it up on the next launch.
  </Step>

  <Step title="Add the CLAI server entry">
    Merge the following into your `claude_desktop_config.json`. If the file already has an `mcpServers` object, add the `"clai"` key inside it.

    ```json
    {
      "mcpServers": {
        "clai": {
          "command": "clai",
          "args": ["start", "--stdio"],
          "cwd": "/path/to/your/project"
        }
      }
    }
    ```

    <Tip>
      The `cwd` field must point to the directory that contains your `clai.config.json`. CLAI reads that file on startup to discover your documentation sources — if the path is wrong, no tools will load.
    </Tip>
  </Step>

  <Step title="Restart Claude Desktop">
    Fully quit Claude Desktop — don't just close the window — then reopen it. On macOS, right-click the Dock icon and choose **Quit**; on Windows, right-click the system tray icon.

    Once Claude restarts, look for the **MCP icon** (a small plug or tools symbol) in the message input area. Its presence confirms that at least one MCP server connected successfully.
  </Step>

  <Step title="Test the integration">
    Start a new conversation and ask Claude something that requires your documentation:

    > "What does the quickstart guide say?"

    Watch the response — Claude should show a tool-call indicator before answering, signaling that it queried CLAI's `search` or `get_page` tool rather than relying solely on its training data. The answer will be grounded in your actual docs.
  </Step>
</Steps>

## Troubleshooting

<AccordionGroup>
  <Accordion title="CLAI doesn't appear in Claude Desktop">
    Claude Desktop only shows the MCP icon when at least one server connected without errors. Work through this checklist:

    1. **Verify the `cwd` path** — open a terminal, `cd` to that path, and confirm `clai.config.json` is present.
    2. **Confirm `clai` is in your PATH** — run `which clai` (macOS/Linux) or `where clai` (Windows). If the command isn't found, either install CLAI globally or replace `"command": "clai"` with the absolute path to the binary (e.g., `"/usr/local/bin/clai"`).
    3. **Validate the JSON** — paste your `claude_desktop_config.json` into a JSON validator. A single misplaced comma will silently prevent Claude from loading the config.
    4. **Check Claude Desktop logs** — on macOS, open Console.app and filter for `Claude`; on Windows, look in `%APPDATA%\Claude\logs\`.
  </Accordion>

  <Accordion title="Claude returns errors when calling CLAI tools">
    If CLAI appears but tool calls fail, the server started but encountered a runtime problem:

    1. **Review your `clai.config.json`** — ensure every source URL or file path is correct and the file is valid JSON.
    2. **Check source reachability** — if your docs are hosted remotely, confirm the URLs respond with a 200 and aren't behind authentication that CLAI hasn't been configured for.
    3. **Run CLAI manually** — in a terminal, `cd` to your project and run `clai start --stdio`. Any startup errors will appear in stderr before the server blocks waiting for input.
  </Accordion>

  <Accordion title="Claude ignores CLAI and answers from training data">
    Claude autonomously decides when to invoke tools based on conversational context. If it doesn't reach for CLAI, try being explicit:

    > "Search my documentation for information about authentication."
    > "Use the CLAI search tool to look up the API rate limits."

    You can also start your message with: *"Before answering, search my docs for…"* — this reliably triggers a tool call. Claude will not call tools if it judges its training data sufficient, so phrasing the question in a way that signals "look this up" helps.
  </Accordion>
</AccordionGroup>
