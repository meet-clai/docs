CLAI is built on the **Model Context Protocol (MCP)** — an open standard by Anthropic that gives AI applications a structured, secure way to call external tools and retrieve live data. Rather than baking your documentation into a model's weights, MCP lets an AI assistant reach out to CLAI at query time, get exactly the content it needs, and form a precise answer — all without leaving your workflow.

## The MCP Architecture

Every MCP integration involves three components working together:

1. **MCP Host** — the AI application the user interacts with directly, such as Claude Desktop, Cursor, or VS Code Copilot. The host manages the conversation and decides when to invoke external tools.
2. **MCP Client** — a protocol layer embedded inside the host. It speaks JSON-RPC 2.0, negotiates capabilities with the server, and routes tool calls back and forth.
3. **MCP Server (CLAI)** — the process that registers tools, receives requests from the client, and returns results. CLAI is the server: it reads your documentation, exposes search and retrieval tools, and responds to every query with real content from your docs.

When you register CLAI with an MCP host, the host discovers CLAI's available tools automatically through a capability handshake. From that point on, the AI can call those tools whenever a user's question warrants it.

## What Happens When You Ask a Question

<Steps>
  <Step title="You ask your AI assistant a question">
    You type something like *"How do I configure OAuth in this project?"* into Claude Desktop, Cursor, or any other MCP host. The AI evaluates the question and determines that a documentation lookup would produce a better answer than relying on its training data alone.
  </Step>

  <Step title="The AI client calls CLAI's search tool">
    The MCP client inside your AI host sends a `tools/call` request to CLAI over the configured transport (STDIO or HTTP). The request includes the query text and any parameters the AI decided to pass based on the tool's schema.
  </Step>

  <Step title="CLAI searches your configured doc sources">
    CLAI receives the request, resolves the query against your configured documentation sources, and finds the most relevant pages. It reads content directly from those sources — no separate indexing pipeline required.
  </Step>

  <Step title="CLAI returns the matching content">
    CLAI sends back a structured response containing the relevant page content, titles, and URLs. The response conforms to the MCP tool result schema so the host can parse it reliably.
  </Step>

  <Step title="The AI composes a grounded answer">
    Your AI assistant receives the doc content and uses it as authoritative context to formulate its response. The answer it gives you is grounded in your actual documentation — not in whatever it may have learned during training.
  </Step>
</Steps>

## CLAI's MCP Tools

CLAI exposes three tools that MCP hosts can call at any point in a conversation.

<CardGroup cols={3}>
  <Card title="search" icon="magnifying-glass">
    Accepts a natural-language query and returns the most relevant documentation passages ranked by relevance. This is the tool AI assistants call most often.
  </Card>
  <Card title="list_pages" icon="list">
    Returns a structured list of all pages available across your configured documentation sources — titles, paths, and metadata.
  </Card>
  <Card title="get_page" icon="file-text">
    Fetches the full Markdown content of a specific documentation page by its path or URL. Useful when the AI needs complete context for a particular topic.
  </Card>
</CardGroup>

## Transport Modes

CLAI supports two transport modes. Choose based on where CLAI runs and who needs to access it.

<Tabs>
  <Tab title="STDIO (Local Process)">
    In STDIO mode, CLAI runs as a child process of your AI host, communicating over standard input/output streams. The host starts and stops CLAI automatically — you never manage a separate server.

    **Best for:** Claude Desktop, Cursor, and any single-user local setup.

    Start CLAI in STDIO mode:

    ```bash
    clai start --stdio
    ```

    Register it in your Claude Desktop config:

    ```json
    {
      "mcpServers": {
        "clai": {
          "command": "clai",
          "args": ["start", "--stdio"]
        }
      }
    }
    ```

    STDIO mode requires no open ports and works entirely offline once your sources are cached.
  </Tab>
  <Tab title="Streamable HTTP (Remote Server)">
    In HTTP mode, CLAI runs as a persistent server that accepts MCP requests over Streamable HTTP — a transport that supports both request/response and server-sent event streaming. Multiple clients can connect to the same CLAI instance simultaneously.

    **Best for:** Team deployments, CI environments, and any scenario where multiple developers share a single CLAI server.

    Start CLAI in HTTP mode:

    ```bash
    clai start --http --port 3000
    ```

    Connect an MCP client by pointing it at your server's endpoint:

    ```text
    http://localhost:3000/mcp
    ```

    In production, deploy CLAI behind a reverse proxy (such as nginx or Caddy) and secure the endpoint with authentication headers configured in your `clai.config.json`.
  </Tab>
</Tabs>

## Doc Sources

A **source** is any location CLAI can read documentation from. You define sources in your `clai.config.json` and CLAI reads from them whenever a tool is called.

CLAI supports three source types:

- **URL** — A remote endpoint, typically an `llms.txt` file or a hosted Markdown page. CLAI fetches the content over HTTP at query time.
- **Local path** — A directory or file on your local filesystem. Useful for docs that live in your repo alongside your code.
- **llms.txt** — A dedicated source type for the `llms.txt` standard. CLAI parses the listing, discovers all referenced pages, and makes them individually retrievable via `get_page`.

Multiple sources can coexist in a single config, so you can mix a local Markdown directory with a remote hosted site seamlessly.

<Tip>
  **Fumadocs users:** Fumadocs generates an `llms.txt` route at `/llms.txt` automatically. Add it as a source in your `clai.config.json` and CLAI will discover every page in your Fumadocs site without any manual configuration.

  ```json clai.config.json
  {
    "sources": [
      { "type": "url", "url": "https://your-fumadocs-site.com/llms.txt" }
    ]
  }
  ```
</Tip>

<Note>
  CLAI never stores or caches a copy of your documentation. Every tool call reads content from your sources on demand, so your AI assistant always sees the current state of your docs — no re-indexing step required.
</Note>
