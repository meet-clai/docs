CLAI uses a `clai.config.json` file in your project root to configure everything — documentation sources, MCP tool settings, authentication credentials, and transport mode. Every aspect of how CLAI fetches and exposes your docs to AI clients is controlled through this single file.

## Config file location

By default, CLAI reads `clai.config.json` from the current working directory when the server starts. If you store your config file elsewhere — for example, in a monorepo where configs live in a shared directory — you can point CLAI to it using the `--config` flag:

```bash
clai start --config ./config/clai.config.json
```

This path can be absolute or relative to the directory from which you invoke the `clai` command.

## Full config reference

The following example shows a complete `clai.config.json` with all supported sections. Each top-level field is optional except `sources`.

```json
{
  "sources": [
    { "type": "url", "url": "https://docs.example.com/llms.txt" },
    { "type": "local", "path": "./docs" }
  ],
  "tools": {
    "search": { "enabled": true, "maxResults": 10 },
    "list_pages": { "enabled": true },
    "get_page": { "enabled": true }
  },
  "auth": {
    "type": "bearer",
    "token": "${DOCS_API_TOKEN}"
  },
  "transport": {
    "mode": "stdio"
  }
}
```

## Config field reference

<ParamField body="sources" type="array" required>
  An array of documentation source definitions. Each source can be a remote URL (including `llms.txt` endpoints), a local file path, or any Markdown-based content location. At least one source is required for CLAI to serve tools to AI clients.

  See [Adding Doc Sources](/guides/adding-docs-sources) for full source schema documentation.
</ParamField>

<Tip>
  **Using Fumadocs?** CLAI has first-class support for Fumadocs sites. Point a `url` source at your Fumadocs `llms.txt` endpoint (for example, `https://your-site.com/llms.txt`) and CLAI will automatically discover all your pages. No extra configuration is needed — Fumadocs' built-in `llms.txt` generation is fully compatible with CLAI's source discovery.
</Tip>

<ParamField body="tools" type="object">
  Controls which MCP tools CLAI exposes and how they behave. You can enable or disable individual tools and tune parameters such as result limits and content length caps. All tools are enabled with their defaults when this field is omitted.

  See [Tools](/configuration/tools) for per-tool configuration options.
</ParamField>

<ParamField body="auth" type="object">
  Global authentication configuration used when fetching content from protected documentation sources. Supports Bearer tokens, API keys, and Basic Auth. Authentication can also be set per source to use different credentials for different endpoints.

  See [Authentication](/configuration/authentication) for all auth types and examples.
</ParamField>

<ParamField body="transport" type="object">
  Defines how AI clients connect to the CLAI server. Set `mode` to `"stdio"` for local process communication (used with Claude Desktop, Cursor, and VS Code) or `"http"` for a Streamable HTTP endpoint suitable for remote deployments. Defaults to `"stdio"` when omitted.
</ParamField>

## Environment variables

Any string value in `clai.config.json` that follows the `${VARIABLE_NAME}` syntax is interpolated from the corresponding environment variable at startup. This lets you keep secrets — API tokens, passwords, and private keys — out of your config file and out of version control.

```json
{
  "auth": {
    "type": "bearer",
    "token": "${DOCS_API_TOKEN}"
  }
}
```

When CLAI starts, it resolves `${DOCS_API_TOKEN}` from the environment. If the variable is not set, CLAI logs a warning and leaves the value as an empty string — authentication will fail, so make sure all referenced variables are present before starting the server.

<Tip>
  Use a `.env` file alongside your `clai.config.json` to manage environment variables locally. Most runtimes and process managers (Node.js with `dotenv`, Docker Compose, Railway, etc.) load `.env` automatically. Add `.env` to your `.gitignore` to keep credentials out of version control.
</Tip>
