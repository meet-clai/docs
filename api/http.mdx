HTTP transport runs CLAI as a web server that any MCP client can connect to over the network — ideal for team deployments and remote documentation access. Unlike STDIO, which is scoped to a single local client, HTTP transport lets multiple AI clients connect to the same CLAI instance simultaneously, from any machine that can reach the server.

## Starting CLAI in HTTP mode

Start CLAI as an HTTP server by passing the `--http` flag and specifying a port:

```bash
clai start --http --port 3000
```

You can also configure HTTP transport in `clai.config.json` to avoid repeating flags on every start:

```json
{
  "transport": {
    "mode": "http",
    "port": 3000,
    "host": "0.0.0.0"
  }
}
```

| Field | Type | Default | Description |
|---|---|---|---|
| `mode` | string | `"stdio"` | Set to `"http"` to enable HTTP transport. |
| `port` | number | `3000` | The port CLAI listens on. |
| `host` | string | `"127.0.0.1"` | The network interface to bind to. Use `"0.0.0.0"` to accept connections on all interfaces. |

## MCP endpoint

Once CLAI is running in HTTP mode, its MCP endpoint is available at:

```
http://localhost:3000/mcp
```

All JSON-RPC 2.0 messages — `tools/list`, `tools/call`, and everything else — are sent to this single endpoint. You can verify the server is up by checking that the endpoint responds before connecting your AI client.

## Connecting a client

Configure your MCP client to connect to CLAI over HTTP by providing the endpoint URL:

```json
{
  "type": "http",
  "url": "http://localhost:3000/mcp"
}
```

Replace `localhost` with the server's hostname or IP address if CLAI is running on a remote machine. Refer to your AI client's documentation for where to place this configuration block — the `type` and `url` fields are standard across MCP-compatible clients.

## Transport protocol

CLAI's HTTP transport implements the Streamable HTTP specification. Client-to-server messages (tool calls, requests) are sent as HTTP POST requests to the `/mcp` endpoint. Server-to-client messages (responses, streamed output) are delivered via Server-Sent Events (SSE) on the same connection.

This design is compatible with any MCP client that supports Streamable HTTP, including recent versions of Claude Desktop, Cursor, and VS Code Copilot. If your client only supports the older SSE-based transport, check the client's changelog for Streamable HTTP support.

## Securing HTTP transport

<Warning>
  Do not expose CLAI's HTTP transport on a public network without authentication. An unauthenticated CLAI endpoint allows anyone who can reach the server to query your documentation sources and call all enabled tools. Always add a bearer token or place CLAI behind a reverse proxy with auth when deploying outside a trusted private network.
</Warning>

Add bearer token authentication to the HTTP transport in `clai.config.json`:

```json
{
  "transport": {
    "mode": "http",
    "port": 3000,
    "auth": {
      "type": "bearer",
      "token": "${CLAI_SERVER_TOKEN}"
    }
  }
}
```

The `token` value supports environment variable interpolation using `${VAR_NAME}` syntax — store your token in an environment variable rather than hard-coding it in the config file.

Once bearer auth is enabled, every client request must include the token in the `Authorization` header:

```
Authorization: Bearer <your-token>
```

Requests that omit or provide an incorrect token receive an HTTP `401 Unauthorized` response. Configure each AI client with the token according to that client's MCP server auth settings.

## When to use HTTP

HTTP transport is the right choice in the following situations:

- **Team environments** — multiple developers share a single CLAI instance connected to your organization's docs
- **Remote or cloud deployments** — CLAI runs on a server separate from the machines where your AI clients run
- **Multiple AI clients** — you want Claude Desktop, Cursor, and VS Code to all connect to the same CLAI server without each running its own local process
- **CI/CD and automation** — scripts or pipelines call CLAI's MCP tools programmatically over HTTP
