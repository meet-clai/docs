---
title: "list_pages Tool: Enumerate All Documentation Pages"
sidebarTitle: "list_pages"
description: "The list_pages MCP tool returns all available documentation pages from configured sources, including titles, URLs, and optional descriptions."
---

`list_pages` gives AI clients a full index of available documentation pages, helping them understand what content is available before searching. When an AI client needs to orient itself — for example, to answer "what topics does your documentation cover?" — it calls `list_pages` to get a complete map of your docs. This works across all supported source types, including Fumadocs projects, standard Markdown sites, and any source discovered via `llms.txt`.

## Tool signature

<ParamField query="source" type="string">
  Filter results to pages from a specific named source as defined in `clai.config.json`. When omitted, `list_pages` returns pages from all configured sources.
</ParamField>

<ParamField query="includeDescriptions" type="boolean" default="false">
  When set to `true`, each page object in the response includes a `description` field containing a short excerpt or meta description for that page.
</ParamField>

## Request example

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "tools/call",
  "params": {
    "name": "list_pages",
    "arguments": {
      "includeDescriptions": true
    }
  }
}
```

## Response

CLAI returns the result inside the standard MCP content envelope. The `text` field contains a JSON-encoded object with the following structure:

<ResponseField name="pages" type="array" required>
  An array of page objects, one per documentation page found across all matched sources.

  <Expandable title="Page object fields">
    <ResponseField name="title" type="string" required>
      The title of the documentation page, extracted from the page's heading or metadata.
    </ResponseField>

    <ResponseField name="url" type="string" required>
      The full URL or file path of the page, depending on whether the source is remote or local.
    </ResponseField>

    <ResponseField name="description" type="string">
      A short excerpt or meta description for the page. Only present when `includeDescriptions` is `true`.
    </ResponseField>

    <ResponseField name="source" type="string" required>
      The name of the configured source this page belongs to, as defined in `clai.config.json`.
    </ResponseField>
  </Expandable>
</ResponseField>

```json
{
  "content": [
    {
      "type": "text",
      "text": "{\"pages\": [{\"title\": \"Introduction\", \"url\": \"https://docs.example.com/introduction\", \"source\": \"main-docs\"}]}"
    }
  ]
}
```

## Configuration

You can control `list_pages` behavior in your `clai.config.json` under the `tools.list_pages` key:

```json
{
  "tools": {
    "list_pages": {
      "enabled": true,
      "includeDescriptions": false
    }
  }
}
```

| Option | Type | Default | Description |
|---|---|---|---|
| `enabled` | boolean | `true` | Set to `false` to disable the tool entirely. Disabled tools return a `CLAI_TOOL_DISABLED` error if called. |
| `includeDescriptions` | boolean | `false` | Sets the default value of the `includeDescriptions` argument for all calls. Can be overridden per-call. |

<Tip>
  On large documentation sites with hundreds of pages, `list_pages` can return a very large payload that occupies significant AI context space. If your AI client is hitting context limits, consider setting `enabled: false` for `list_pages` and relying on `search` instead — it returns only the most relevant content for a given query.
</Tip>
