STDIO transport starts CLAI as a subprocess on the same machine as your AI client — communication happens over stdin/stdout using newline-delimited JSON-RPC 2.0. This is the simplest way to run CLAI and the default transport mode for most desktop AI tools.

## How STDIO transport works

When an AI client is configured to use CLAI over STDIO, it spawns `clai start --stdio` as a child process at startup. Every MCP message — tool calls, responses, errors — is exchanged as a newline-terminated JSON object written to the process's stdin (client → CLAI) or stdout (CLAI → client). When the AI client closes or disconnects, the CLAI process exits automatically.

Because the communication channel is the process's own standard streams, no network port is opened and no additional firewall rules are required. The entire session is local to your machine.

## Starting CLAI in STDIO mode

Run CLAI directly from your terminal to verify the STDIO transport starts correctly:

```bash
clai start --stdio
```

You can also set STDIO as the default transport in `clai.config.json`:

```json
{
  "transport": { "mode": "stdio" }
}
```

When `mode` is set to `"stdio"` in the config, running `clai start` without flags uses STDIO automatically.

## Client configuration

All major AI clients that support MCP use the same configuration pattern to launch a STDIO server. Point the client at the `clai` binary and pass `start --stdio` as the arguments:

```json
{
  "command": "clai",
  "args": ["start", "--stdio"],
  "cwd": "/path/to/project"
}
```

| Field | Description |
|---|---|
| `command` | The executable to run — `clai` if it's on your system PATH, or an absolute path otherwise. |
| `args` | Arguments passed to the command. Always include `start --stdio` for STDIO transport. |
| `cwd` | The working directory CLAI starts in. Set this to your project root if your `clai.config.json` lives there. |

Refer to your AI client's documentation for where to place this configuration block. Claude Desktop, Cursor, and VS Code Copilot all accept this exact format in their respective MCP server config sections.

## When to use STDIO

STDIO is the right choice in the following situations:

- **Local development** — you're running CLAI and your AI client on the same machine
- **Single-user setups** — only one AI client needs to connect to CLAI at a time
- **Claude Desktop, Cursor, or VS Code** — all three clients have first-class support for STDIO MCP servers and handle process lifecycle management automatically

## Limitations

STDIO transport supports exactly one client connection at a time. Each AI client spawns its own CLAI process, so if you open Claude Desktop and VS Code simultaneously, each runs its own isolated CLAI instance. This is usually fine for personal use, but it means both processes independently load your documentation sources.

If you need multiple clients to share a single CLAI instance — for example, in a team environment or on a remote server — use [HTTP transport](/api/http) instead.

<Tip>
  If your AI client reports that it cannot find the `clai` command, use the absolute path to the binary instead of the bare name. Run `which clai` (macOS/Linux) or `where clai` (Windows) in your terminal to find the full path, then update the `command` field accordingly — for example, `"/usr/local/bin/clai"`.
</Tip>
